# Porting: from design/animations onto a page

A finished animation in `design/animations/<slug>.html` already uses the site's stylesheets and the same build API, so moving it onto a page is mostly moving three blocks: markup, styles, build. What makes it a site change is the paperwork around it, which CLAUDE.md requires and the owner reviews.

Contents: Before you start · Stage onto the homepage · Window onto an industry page · Checks · Commit

## Before you start

1. Ask. Copy, routes and layout are the owner's (CLAUDE.md, "Do not touch without asking"). Say where it goes and what it replaces.
2. **Spec first.** Write the graphic into DESIGN.md, Components, in the voice of the entries around it: a new Step Stage object goes into Step Stage's numbered list with its Motion sentence; anything else gets its own entry (Role, then what it is, then Motion). A component in code but not in DESIGN.md is a bug.
3. **Accent.** If it puts the accent somewhere new, add that place to CLAUDE.md, Non-negotiables, rule 3, the way the Step Stages and Industry Graphics are listed there.
4. **Changelog.** A dated line in `design/CHANGELOG.md` saying what changed and why.

All four in the same commit as the code.

## Stage onto the homepage

The homepage is written by hand (`index.html`), styled by `styles/home.css`, and its stages run on `site.js`.

1. **Markup.** Copy the `<figure class="stage panel" data-demo="<slug>">` into place in `index.html`. Under How it works it sits as the second child of a `<article class="step rise mo">`, after the `.step-top` copy; a stage on its own needs a container with `container-type: inline-size` so its ratio rules apply.
2. **Styles.** Move the rules from the file's own `<style>` into `styles/home.css`, after the existing Step Stage rules (`/* 4. what it earned */` and the `@container (max-width:400px)` block). Keep them scoped to the figure. Drop the review-page rules (`.ls-frame`, `html.is-rec`).
3. **Build.** Copy the build function into `site.js`, "Step stages", as a new key of `BUILD`. The API is the same; two differences:
   - `site.js`'s `Loop` has no `t.seg` (stages have no ring). Remove those calls.
   - Its `t.at` and `t.count` run on timers rather than one clock. Your build does not change, but a pause does not exist there (stages have no pause control), so nothing is lost.
   The return value is ignored there; it waits for every animation's `finished`.
4. The stage starts when it is 30% on screen; nothing else to wire.

## Window onto an industry page

Industry pages are generated by `tools/` (never edit their HTML by hand), styled by `styles/site.css`, and their graphics run on `ui.js`.

1. **Markup.** Write the figure into the page's generator (`tools/page_industry.py`, or `tools/page_collections.py` for /collections), in the section it illustrates. Change `data-demo="<slug>"` to `data-ig="<key>"`, keep the classes `ig`, `ig-bar`, `ig-body`, `ig-foot`, and the ring button (`data-toggle`, `hidden`) as the other graphics write it. The section header is the figure's caption (DESIGN.md, Industry Section).
2. **Styles.** Into `styles/site.css`, after the Industry Graphic rules (`.ig-week`, `.ig-clock`), scoped to `.ig-<key>`.
3. **Build.** Into `ui.js`, "Industry graphics", as a new key of `BUILD`. That runner's API is smaller: `function (a, fig) { ...; return end; }`, where `a(node, frames, at, dur, ease, fill)` is `t.add`. Translate:
   - `t.rise(n, at)` becomes `a(n, [{ opacity: 0, transform: UP }, { opacity: 1, transform: ZERO }], at, ENTER)`.
   - `t.fade(n, at)` becomes `a(n, [{ opacity: 0 }, { opacity: 1 }], at, BASE, STD)`.
   - `t.at(time, fn)` and `t.count`: attach the change to the beat it belongs to with `x.onfinish` (as `week` does for its counter), and set `fig._restore` to put the shipped text back.
   - `t.seg`: the industry graphics' rings are pause controls only; drop it.
   The runner fades `.ig-body` and `.ig-foot` between loops and handles the ring, off screen and reduced motion.
4. `python3 tools/build.py` and commit its output with the source.

## Checks

From the repo root, all must pass (CLAUDE.md, "Before you finish any task"):

```bash
node scripts/check-tokens.mjs
node scripts/check-structure.mjs
node scripts/check-build.mjs
node scripts/check-contrast.mjs
node scripts/snapshot.mjs <stage-name>
```

Then look at the snapshot of the page in both themes at 1440 and 390, and watch the graphic loop on the page itself (`node scripts/dev-server.mjs`): it should start only after its block has risen, stop when scrolled away, and rest finished under reduced motion.

## Commit

One commit: the markup or generator change, the styles, the build, the build output for generated pages, DESIGN.md, CLAUDE.md (if the accent moved), and `design/CHANGELOG.md`. The standalone file in `design/animations/` can stay as the graphic's workbench.
